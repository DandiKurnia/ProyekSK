# 2026-11-01 — Oval Presence-Driven di `/camera` & `/students/enroll`

> Changelog harian. Format: Apa → Kenapa → File terdampak → Status uji.

## 1. Oval reticle jadi indikator kehadiran wajah (bukan hasil match)

- **Apa:** Oval di kedua halaman sekarang diwarnai oleh `faces_detected` live dari `POST /api/face/recognize`, bukan oleh hasil scan terakhir.
  - `facePresent: boolean | null` (`null` = belum diprobe) → hijau `border-emerald-400` (wajah ada di frame), merah `border-rose-500` (tidak ada), abu `border-white/60` (belum probe).
  - Label: `Wajah Terdeteksi — Siap Scan` / `Wajah Terdeteksi — Siap Ambil` / `Wajah Tidak Terdeteksi` / `Posisikan Wajah di Oval`.
  - `/camera` saat memindai: oval kuning `border-amber-400` berdenyut + label `Memindai...` (prioritas di atas status presence).
- **Kenapa:** Sebelumnya hijau berarti "sudah match" (hasil scan lama), sehingga oval tetap hijau walau wajah sudah pergi, dan merah tidak pernah muncul saat frame kosong. Warna harus mencerminkan kondisi frame sekarang; hasil match tetap ditampilkan di kartu status.
- **Probe:** interval ringan 1.2 dtk, frame 320 px JPEG `0.6`, terpisah dari lock `scanning` (manual/auto 1.8 dtk tidak terpengaruh). Gagal jaringan → warna mempertahankan status terakhir, tidak flip-flop.

## 2. `/students/enroll` — capture diblokir saat wajah tidak ada

- **Apa:** `captureSample()` return lebih awal bila `facePresent === false` → banner error "Wajah tidak terdeteksi. Posisikan wajah di dalam oval hijau sebelum mengambil sampel."
- **Kenapa:** Sampel dari frame kosong/bergerak merusak kualitas embedding rata-rata 5 sudut.
- **Detail:** `presenceBusyRef` mencegah probe bertumpuk saat request lambat; sampling per-sudut (`captureSample(g.id)`) tetap boleh overwrite slot yang sudah terisi.

## 3. Fix 5 bug nyata di `/camera`

1. **Crop oval vs geometri video:** frame dulu di-crop ke oval 3:4 + luar oval dihitamkan, padahal oval UI digambar di video `object-cover` 4:3 — wajah yang tampak di dalam oval bisa terbuang crop atau black-mask menutupi pipi. **Fix:** kirim frame utuh tanpa mask; oval murni panduan visual (YuNet tidak butuh mask).
2. **Auto-scan interval ter-reset tiap tick:** `captureAndRecognize` ada di dep array → `setScanning` tiap scan membangun ulang `setInterval` 1.8 dtk sehingga tick tidak stabil/tidak pernah tepat waktu. **Fix:** `scanRef` + interval tetap, dep hanya `[autoScan, streamActive]`.
3. **Tombol scan saat `scanning`:** disabled hanya bila tidak ada wajah → diganti: boleh scan kapan saja, hasil dilaporkan "tidak ada wajah".
4. **`captureAndRecognize` mengembalikan `depends on scanning`** → debounce/guard di level interval, bukan di callback.
5. **`stopCamera` tidak membersihkan `facePresent`** → sekarang di-reset `null` agar oval kembali netral saat kamera mati.

## 4. Operasional — port uji nyangkut

- **Gejala:** `next start --port 3100` gagal `EADDRINUSE :::3100`; halaman lama sempat menampilkan `ChunkLoadError` karena proses lama menyajikan build dengan hash chunk berbeda.
- **Fix:** cari PID dengan `netstat -ano | findstr ":3100" | findstr LISTENING` → `Stop-Process -Id <PID> -Force`. Port 3001 dan 3100 sekarang bebas.
- **Catatan:** `next start` menyajikan `.next/` dari build terakhir — bila ada server lama masih hidup, aset 404/abort meski HTML 200.
