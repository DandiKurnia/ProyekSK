## 1. Otak Penentu Absensi di `POST /api/attendance` (Supabase + 2FA Anti-Replay)

- **Apa:** Route Handler `POST /api/attendance` dijadikan satu-satunya otoritas yang menetapkan status absensi (`present`, `late`, `failed`, `expired`). Client web tidak dipercaya menetapkan status.
  - Verifikasi bukti 2FA ke face-service (`GET :8200/fingerprint/session`): harus `verified`, slot fingerprint cocok dengan `students.fingerprint_slot`, dan umur bukti `verified_at <= 120` detik (anti-replay).
  - Penentuan keterlambatan server-side: membaca `app_config.late_threshold` (format HH:mm WIB, misal `07:15`), fallback `present` bila config kosong.
  - Idempoten: `upsert` pada `(student_id, class_id, date)`. Scan ulang di hari yang sama mempertahankan waktu check-in pertama (`onConflict: student_id,class_id,date`).
  - Audit kegagalan: status `failed` / `expired` di-insert terpisah (tanpa menimpa baris `present` yang sudah sah sebelumnya).
  - Konsumsi sesi 1x: setelah tersimpan, Route Handler memanggil `DELETE :8200/fingerprint/session` agar bukti tidak bisa dipakai ulang, dilanjutkan `POST :8200/fingerprint/led` untuk kedip cincin LED hijau di sensor R503 sebagai umpan balik fisik ke siswa.
  - `GET /api/attendance` ditambah filter `status` (`present`, `late`, `failed`, `expired`, `all`) + integrasi Supabase pagination & dynamic class list.
- **Kenapa:** Menutup celah kecurangan bila client browser dimanipulasi; konsisten dengan arsitektur `prd-attendance.md` §3 langkah 5.

## 2. Integrasi Sensor Fingerprint R503 via Serial USB CDC

- **Apa:** Komunikasi ESP32 R503 dialihkan penuh dari konsep lama (Wi-Fi polling) ke **kabel USB Serial** ke Host PC kelas (`apps/face-service/fingerprint_serial.py`).
  - Driver `FingerprintBridge` membaca event asinkron dari firmware `esp32R503_Serial.ino`: `READY`, `PLACE`, `REMOVE`, `MATCH <slot> <score>`, `NOMATCH`, `TIMEOUT`.
  - Protokol berbasis teks spasi: `PING`, `ENROLL <slot>`, `DELETE <slot>`, `CLEAR`, `LED_OK`.
  - Wasit sesi 2FA hidup di `face-service`: state machine (`waiting` → `verified` / `failed` / `expired`), maksimal 3x coba, TTL 30 detik, tracking `verified_at`.
  - 7 endpoint HTTP di `server.py`: `/fingerprint/status`, `/fingerprint/enroll`, `/fingerprint/enroll/status`, `DELETE /fingerprint/{slot:int}`, `/fingerprint/session` (POST/GET/DELETE), dan `/fingerprint/led`.
  - Web UI: panel 2FA live di `/camera` (countdown 30 dtk, sisa percobaan, auto-reset 3.5 dtk, cooldown re-scan 30 dtk) dan step enrollment sidik jari di `/students/enroll` (alokasi slot 1..200 otomatis, rollback DB bila gagal).
