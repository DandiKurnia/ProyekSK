## 1. Faktor kedua: jari **ATAU** kartu

- **Apa:** Absensi 2FA sekarang sah bila wajah cocok **dan** (slot jari cocok **atau** UID kartu terikat cocok). Kartu tidak menambah faktor ketiga.
  - `rfid_cards (uid PK, student_id FK, created_at)` — satu siswa boleh banyak kartu, satu kartu hanya satu siswa.
  - `POST /api/fingerprint/session` mengirim `uids` terikat ke face-service bersama `slot`; siswa kartu-saja (`fingerprint_slot` NULL, punya kartu) boleh membuka sesi.
  - `POST /api/attendance` menerima `matched_uid` dari face-service; `412` bila faktor kedua tidak cocok, `403` bila siswa belum enroll jari maupun kartu.
  - Baris `attendance` hasil kartu: `fingerprint_slot = NULL`, `face_confidence` terisi. **Tidak ada** kolom `rfid_uid` — jangan ditambah tanpa migrasi.
- **Kenapa:** R503 dan RC522 satu board; siswa tanpa sidik jari layak (jari terluka, kulit kering, disabilitas) tidak boleh terkunci dari absensi.
- **File:** `apps/face-service/fingerprint_serial.py`, `apps/face-service/server.py`, `apps/web/src/app/api/attendance/route.ts`, `apps/web/src/app/api/fingerprint/session/route.ts`, `apps/web/src/app/api/students/route.ts`, `apps/web/src/app/api/rfid/**` (baru), `apps/web/src/app/students/page.tsx`, `apps/web/src/app/students/enroll/page.tsx`, `esp32R503_Serial/esp32R503_Serial.ino`.

## 2. Firmware ESP32 v1.1 — reader RC522

- **Protokol baru (PC → ESP32):**
  - `CARD` → `CARDWAIT` (jendela daftar 15 dtk) → `CARD_OK <UID>` atau `CARD_TIMEOUT`; tanpa reader → `CARD_FAIL 0`.
  - `CANCEL` → tutup jendela tanpa hasil.
- **Event baru (ESP32 → PC):** `RFID_FAIL 0` (RC522 tidak terdeteksi, firmware tetap jalan), `CARD <UID>` (tap bebas, termasuk di luar sesi), `CARD_OK`, `CARD_TIMEOUT`, `CARDWAIT`.
- **Loop:** prioritas `Serial` → cek batas waktu jendela kartu → `cekKartu()` non-blocking → `verifikasi()`. UID di-debounce 2 dtk agar tap ganda tidak mengirim event beruntun.
- **Wiring:** RC522 pada SPI VSPI — SCK 18, MISO 19, MOSI 23, SS 5, RST 27.
- **Belum diuji perangkat:** tidak ada `arduino-cli` di mesin ini dan library `MFRC522` belum terpasang, jadi sketsa belum dikompilasi. Butuh `Adafruit Fingerprint Sensor` + `MFRC522`.

## 3. Driver serial (`fingerprint_serial.py`)
- Sesi menyimpan `uids` terikat siswa; `MATCH` slot ≠ slot sesi dan `CARD` UID ≠ `uids` keduanya menambah percobaan (3x → `failed`, alasan `slot_mismatch` / `uid_mismatch`).
- `open_card()` / `card_status()` / `cancel_card()`: jendela daftar kartu dengan deadline sendiri, dipolling UI tiap 700 ms.
- `status()` kini melaporkan `last_card` + status jendela kartu.

## 6. Fix `500 KeyError: 'error'` pada `POST /rfid/enroll`

- **Gejala:** klik "Daftarkan Kartu RFID" → face-service HTTP 500. Traceback: `server.py:386 hasil["error"]` → `KeyError: 'error'`.
- **Akar:** `open_card()` mengembalikan `{"ok": True, **card_status()}`, tetapi `card_status()` sendiri membawa kunci `ok: None` (status jendela, bukan status perintah). Spread menimpa `ok: True` → `None` → server mengira gagal lalu membaca `hasil["error"]` yang tidak ada. Bug ini menggagalkan enroll kartu **meski serial terhubung**.
- **Fix:**
  - `fingerprint_serial.py`: `open_card()` memakai kunci `started`, bukan `ok`, agar tidak bentrok dengan `ok` milik `card_status()`.
  - `server.py`: `rfid_enroll` mengecek `hasil.get("started")` dan memakai `hasil.get("error", ...)` (tidak lagi meledak `KeyError`).
- **Uji:**
  - Self-check + HTTP (`test_fingerprint_bridge.py`): ditambah cek #5 (`POST /rfid/enroll` → 202, `CARDWAIT` → `waiting`, `CARD_OK` → `done ok uid`) dan cek #6 (serial mati → **503**, bukan 500). Semua lolos + `SMOKE_API_OK`.
  - Uvicorn live di `:8021`: `GET /health` 200; `POST /rfid/enroll` tanpa serial → `503 {"detail":"serial tidak terhubung"}`. Server uji dimatikan setelahnya.
- **Catatan buat user:** restart uvicorn face-service (`8000`) agar fix ini aktif, lalu ulangi "Daftarkan Kartu RFID" — dengan ESP32 tercolok harusnya sekarang 202 + jendela 15 dtk.
